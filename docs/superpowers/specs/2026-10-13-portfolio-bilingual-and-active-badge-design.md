## 1. 目的与当前事实

中文版让国内公司的招聘方直接读懂个人定位、经历和项目；英文版继续服务英文读者。两种语言都有可分享、可直接访问、可被搜索引擎发现的页面地址。

可以把它理解为同一份履历的两个语言版本：项目事实和链接共用，介绍文字各有一份。只翻导航而保留英文经历，无法满足国内招聘方的阅读需求。

本轮已确认：

- 仓库仍是 React 19、TypeScript、Vite 7、React Router 与 Tailwind CSS 4，Next.js 尚未迁移。
- `Portfolio.tsx` 和 `LabPage.tsx` 都以 `demoUrl` 是否存在决定 Active 徽章显示，没有独立开关。
- 原计划只要求英文内容，并固定 Space Grotesk / DM Sans 字体；本规格替代这两项限制。
- Header 有跨页面使用 `window.location.href` 的跳转，现有 ScrollManager 在 pathname 改变时滚到顶部。迁移时不能沿用这些行为处理语言切换。
- Chatbot 位于右下角，移动端展开为全屏；UpdatesWidget 位于右侧中部。
- 当前工作区存在未提交的源码、简历和删除变更。本轮只修改忽略规则和文档，不据此宣称 Phase 1 完成。

## 3. 范围与边界

### 3.1 本规格覆盖

- 一个共享 ActiveBadge 组件、项目级显示开关以及两个展示位置。
- 英文与简体中文的首页、Lab、博客列表界面。
- Header、Footer、主题按钮、联系表单、聊天面板、更新组件的标签、提示、加载态、空态、错误态和无障碍名称。
- 中文个人介绍、教育、经历、项目描述与亮点、技能分类、联系说明、Hero 轮播文案。
- Next.js 多语言路由、静态生成、页面元数据、语言关联、旧地址兼容、站点地图。
- 字体本站托管、中文排版和语言切换的状态保留。

### 3.2 内容规则

- 中文介绍依据现有中文简历及已核实项目资料编写；英文介绍依据 Phase 1 的实际完成内容。不得新增未经确认的经历、数字或服务可用性声明。
- 项目品牌、技术名称、邮箱、代码和 URL 保留原名。可翻译说明性项目标题，不翻译品牌名称。
- 中英文内容中的项目、经历、年份、指标、链接和排序对应一致。
- 简历下载按语言指向现有文件：英文 `public/Huizhirong Guo.pdf`，中文 `public/过汇智融-中文简历.pdf`。不在本规格内重写 PDF；其内容正确性仍须人工核对。
- 博客文章标题、摘要、正文、标签和代码保留原内容，中文列表明确标注“英文文章”。博客阅读时间、筛选、返回等界面文字可翻译。
- Git 提交消息和聊天历史属于内容，不因切换语言被翻译或改写。新聊天回复如何选择语言属于现有聊天行为及 Phase 4 的范围。

### 3.3 本轮不包含

博客翻译、在线翻译服务、翻译管理平台、CMS、自动检测 IP 后强制切换语言、框架之外的额外 i18n 依赖、新增服务供应商、Demo 服务修复，以及 Phase 2/4 的重新设计。

## 4. Active 徽章

`showActiveBadge` 表示“是否展示徽章”，不表示系统已经探测该项目正在运行。

- 项目类型声明必填布尔字段，现有每个项目显式设置为 `false`。
- 首页与 Lab 通过同一个 ActiveBadge 组件读取该字段。组件在关闭时不输出徽章，也不占用空白位置。
- 以后修改一个项目的字段，两处展示同步改变；无需修改组件条件或复制徽章样式。
- `demoUrl` 只决定 Demo 按钮是否显示；`githubUrl` 继续决定源码按钮是否显示。
- 中文徽章文案为“运行中”，英文为“Active”；重新启用前由维护者确认此表述准确。没有 Demo 的项目也不被技术上禁止展示徽章。
- Phase 1 先接入英文徽章；Phase 3 接入字典中的双语标签，继续保留同一组件与开关。

## 5. 路由与语言来源

语言由 URL 决定。字典负责提供文字，不另建一套会与 URL 冲突的当前语言状态。

以下是本规格已批准的地址约定：

| 页面 | 英文正式地址 | 中文正式地址 |
|---|---|---|
| 首页 | `/en` | `/zh` |
| Lab | `/en/lab` | `/zh/lab` |
| 博客列表 | `/en/blog` | `/zh/blog` |
| 博客文章 | `/en/blog/[slug]` | 无中文文章版本 |

- URL 语言值只接受 `en`、`zh`；HTML 的 `lang` 分别为 `en`、`zh-CN`。未知语言及不存在的文章返回 404，不默默改成英文。
- `/`、`/lab`、`/blog`、`/blog/[slug]` 分别永久跳转到对应英文正式地址，采用 HTTP 308。旧首页的 `#contact` 等锚点必须继续有效。
- `/zh/blog/[slug]` 不渲染重复英文正文；对存在的文章永久跳转到英文正式地址，不存在的文章返回 404。
- API 仍使用 `/api/*`，资源和 PDF 地址不增加语言前缀。
- `/` 默认跳到英文；不根据 IP、浏览器语言、cookie 或 localStorage 自动改变页面。用户分享 `/zh` 就明确分享中文版，刷新和新标签页也保持该语言。
- 中文博客列表链接到英文文章，点击前明确告知“英文文章”；文章页面使用英文界面和 `lang="en"`。
- 文章页面的语言入口提供明确的“中文目录 / Chinese index”链接，前往 `/zh/blog`，不声称能翻译当前文章。

Next.js App Router 使用 `app/[lang]` 表达两种语言，通过 `generateStaticParams` 在构建时生成页面。SSG（静态生成）指提前生成 HTML，访问时不逐次渲染作品集内容。两种语言共用根布局定义；避免采用两个独立语言根布局造成整页重新加载。

## 6. 内容与组件结构

- `lib/i18n/` 定义支持语言、字典类型、语言校验和对应页面地址映射；UI 字典分别存为英文、中文文件。
- `lib/content/` 继续作为组件访问内容的入口。作品集接口接受语言参数，博客内容接口仍只有一份英文源。
- 项目的稳定 ID、图片、年份、技术栈、链接、`featured` 和 `showActiveBadge` 放在共享数据中；按 ID 关联中英文展示文字。经历、教育等重复实体同样保持稳定标识。
- 翻译按语言分文件，不把所有字段改成 `{ en, zh }` 后分散到 JSX 中读取，也不复制两套项目元数据。
- 服务端读取当前语言的字典及内容，客户端组件只接收需要的文案。语言入口使用框架导航到对应地址，UI 所需的 locale 来自路由或路由派生的共享 provider。
- 缺失中文静态翻译应在构建或校验阶段报错；不得在产品页面静默混入英文。品牌名称和明确标识的英文内容除外。
- API 返回的已有错误在展示层映射为可翻译文案；未知错误使用当前语言的通用提示，不把原始内部错误直接作为产品文案。
- 不对页面整体使用 `key={locale}` 强制重建所有组件。

## 7. 语言切换体验

桌面宽度 `>= 768px` 显示左下角 44×44 单个入口：英文页显示目标“中”，中文页显示目标“EN”，完整操作名称由无障碍标签及悬停/键盘聚焦提示表达。文章页仍显示紧凑“中”，名称与提示明确为“中文目录 / Chinese index”，链接前往 `/zh/blog`；提示可用 Escape 关闭。更窄屏幕只在汉堡菜单显示“English / 简体中文”两项并标识当前语言，文章菜单中文项仍明确为中文目录。鼠标、触屏和键盘均可操作；入口须避开安全区域和既有浮层，桌面按钮切换后保留键盘焦点。

语言导航使用 Next.js Link 或路由 API，可预取目标页面；不使用 `window.location.href`。预取失败时仍可正常导航，不承诺零网络请求。

对首页、Lab、博客列表的对应语言切换：

- 保留当前页面类型、查询参数和仍有效的锚点，使用新增历史记录的导航，浏览器后退能回到上一语言。
- 首页优先保留当前浏览章节及章内相对位置，不因翻译长度变化跳到页首；其他页面保留当前滚动位置并限制在新页面有效范围内。
- 主题不变；聊天会话 ID、已有消息、输入草稿和正在进行的回复不被清空或重新请求；联系表单已输入字段保留。
- 菜单选择后关闭，焦点返回可用的语言入口；切换中防止重复提交导航。失败时保留原页面与输入，允许重试。
- 共享状态放在可跨语言导航保持的客户端边界中，具体生命周期在 tickets 阶段以实际 Next.js 版本验证。浏览器刷新后的聊天恢复不新增为本次要求。

首版以无整页刷新、文字稳定替换为验收基线。不复用主题涟漪，不引入实验性页面过渡依赖。Hero 切换后重置到新语言第一句，旧计时器清理，不同时运行两套打字机；滚动入场动画不因语言切换整页重新播放。开启减少动态效果的系统偏好时，Hero 使用静态文字，禁用非必要动画。

## 8. 字体与中文排版

- 标题、正文、按钮与表单统一使用 Noto Sans SC；代码块继续使用等宽字体。标题层级通过字号和字重表达。
- 字体由本站域名提供，使用 Next.js 字体工具或本地字体文件。访客浏览器不再请求 Google Fonts 字体服务。
- 使用 WOFF2（面向网页的压缩字体格式），只加载需要的字重；优先按字符范围拆分或对子集做优化，避免整包中文字库阻塞首屏。保留字体随附许可证。
- 首页首次加载实际传输的字体响应体合计以 **500 KiB 为上限**，中英文、冷缓存分别记录。超限须优化或回到用户审核，不作为已通过验收。
- 静态中文内容必须覆盖完整字形；聊天中的未知字符允许回退到系统字体。回退栈明确包含 PingFang SC、Microsoft YaHei、sans-serif；下载失败时页面仍可读。
- 中文段落使用适合阅读的行高和宽度，避免继承英文标题的大字距；长技术名、URL、标签可以安全换行，代码块允许横向滚动。
- 在 375px、768px、1440px 宽度及深浅主题下检查导航、Hero、经历、项目卡片、表单和悬浮入口。

## 9. SEO

SEO（搜索引擎优化）在本次指让爬虫获取可读的对应语言内容，并准确识别正式页面与语言对应关系，不包含排名或收录时间保证。

- 中英文页面在 JavaScript 执行前就提供对应语言的主体内容、HTML `lang`、标题、描述和社交分享元数据。
- 生产正式域名使用 `https://www.plonguo.com`；2026-10-15 上线检查确认现有 apex→www 永久跳转，用户明确批准保留 www 主域并统一 SEO。此决定覆盖原计划不带 www 的地址；元数据不混入 localhost 或预览地址。
- 每个正式页面声明指向自身的 canonical（正式地址声明），中文不能统一指向英文首页。
- 真正有双语对应的页面设置双向 hreflang（语言版本关联）：`en`、`zh-CN`；默认版本 `x-default` 指向相应英文页面。
- 英文文章提供文章自己的标题、摘要、canonical 和分享信息；不声明中文文章 hreflang。
- sitemap（站点地图）包含两种语言的首页、Lab、博客列表，以及每篇英文文章一次；不收录旧跳转地址或不存在的中文文章。
- robots.txt 指向正式 sitemap，生产页面不被误设为 `noindex`；预览环境继续防止被收录。
- 语言入口和旧链接兼容允许爬虫发现两套页面，中文内容不依赖 localStorage 或 cookie 才出现。

以下是规格验收条件，不是执行 tickets；实施阶段须记录实际命令、截图或响应证据。未执行的项目应明确写“未验证”。

## 12. 依据

- [Next.js 多语言指南](https://nextjs.org/docs/app/guides/internationalization)：语言路由、字典、静态生成和 HTML lang。
- [Next.js 客户端导航](https://nextjs.org/docs/app/getting-started/linking-and-navigating)：客户端导航与预取。
- [Next.js 页面元数据](https://nextjs.org/docs/app/api-reference/functions/generate-metadata)：canonical 与语言关联。
- [Google 多语言网站指南](https://developers.google.com/search/docs/specialty/international/managing-multi-regional-sites)：不同语言使用独立 URL，避免只通过客户端偏好显示翻译。
- [Next.js 字体优化](https://nextjs.org/docs/app/getting-started/fonts)、[Noto CJK](https://github.com/notofonts/noto-cjk)：字体托管方式与字体资源。字体选择和预算是本项目的设计要求。
